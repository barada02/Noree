02

What V1 is

The core flow: open a project, add a Slate, write by hand and ask the AI. Add a 3D block, draw a line from the Slate to it and press Generate. Everyone on the link sees all of this live, including the AI's work.

Four things that must work

  1. A board with blocks you can move, group and connect.
  2. A Slate block where handwriting gets real AI annotations and live widgets.
  3. Connections that pass one block's content to another block's AI.
  4. A 3D block whose Generate button runs the agent, sandbox test and review pipeline.

Multiplayer is the fifth. It stays unless the M2 gate fails.

Not in V1

Accounts, a free-form assistant, agent routing and orchestration, Image, Segment, Diagram, Video and Kanban blocks, voice input, PDF export, and a real database. All are on the later list.

04

Architecture

Three rules

  1. The Y.Doc is the source of truth. The UI draws what's in the document and keeps no second copy of board data.
  2. Agents are participants. Agents write results into the shared document, so every person sees them live. An agent never talks to one browser.
  3. HTTP only starts work. A POST returns a job id right away. Progress and results arrive through the document, which replaces today's SSE stream.

Request paths

nginx strips /api, so Nest never sees that prefix. The Vite dev proxy does the same, so local and production behave alike.

Data model

One Y.Doc per project, named project:<uuid>. Layout and content are stored apart, so moving a block never touches a large Slate page.

doc
├── meta:    Y.Map                { title, createdAt, schemaVersion }
├── blocks:  Y.Map<id, Y.Map>     layout for each block and frame
├── edges:   Y.Map<id, Y.Map>     { source, target, createdBy }
├── order:   Y.Array<id>          frame order for sidebar, Read view, export
├── content: Y.Map<id, Y.Map>     block content, by type
├── threads: Y.Map<id, Y.Array>   chat messages, per block
└── jobs:    Y.Map<id, Y.Map>     running and finished AI work
type BlockType = 'frame' | 'text' | 'sticky' | 'slate' | 'model3d'
type ActorRef  = { kind: 'person' | 'agent'; id: string; name: string }

interface BlockLayout {
  id: string; type: BlockType; title: string
  x: number; y: number; w: number; h: number   // relative to parent when parentId is set
  parentId: string | null                      // frame id
  createdBy: ActorRef
}

interface SlateContent {                       // text and sticky hold one Y.Text instead
  pages: Y.Array<SlatePage>
  currentPageId: string
}
interface SlatePage {
  id: string
  strokes: Y.Array<Stroke>                     // finished strokes only
  objects: Y.Map<AiObject>                     // same AiObject type as ink-agent
  widgetValues: Y.Map<unknown>                 // Argand point, sliders
  pastes: Y.Array<PageItem>                    // pasted text or image on the page
  snapshotAsset: string | null                 // PNG, so the server can read this page
  transcript: { hash: string; text: string } | null
}

interface Model3dContent {
  prompt: string
  versions: Y.Array<{
    id: string; entryId: string; status: 'approved' | 'draft'
    codeAsset: string; previewAsset: string | null
    inputHash: string                          // detects "out of date"
    createdBy: ActorRef; createdAt: number
  }>
  currentVersionId: string | null
}

interface Job {
  id: string; blockId: string
  kind: 'slate-run' | 'generate-3d' | 'chat'
  status: 'running' | 'done' | 'failed' | 'cancelled'
  steps: Y.Array<{ title: string; status: string; note?: string }>
  startedBy: ActorRef; heartbeatAt: number; error?: string
}

Rules

  • No base64 in the Y.Doc. Images go to the asset endpoint, and the document stores only the URL.
  • Not stored: selection, viewport and cursors. These go through Yjs awareness or stay local.
  • Undo: one Y.UndoManager per person tracks only their changes. Undo AI removes all objects with the job's runId.
  • Every change goes through one action layer in shared/actions.ts, with zod schemas and applyAction(doc, action, actor). The same code runs in the browser and on the server, and the future assistant will use it too.
type Action =
  | { type: 'block.add'; blockType: BlockType; at?: Point; parentId?: string; title?: string }
  | { type: 'block.move'; id: string; to: Point }
  | { type: 'block.resize'; id: string; size: Size }
  | { type: 'block.update'; id: string; patch: Partial<EditableFields> }
  | { type: 'block.delete'; id: string }
  | { type: 'frame.assign'; blockId: string; frameId: string | null }
  | { type: 'frame.reorder'; frameId: string; index: number }
  | { type: 'edge.add'; source: string; target: string }
  | { type: 'edge.delete'; id: string }
  | { type: 'slate.page.add'; blockId: string }
  | { type: 'slate.undoRun'; blockId: string; pageId: string; runId: string }
  | { type: 'thread.add'; blockId: string; message: NewMessage }

Binding Yjs to React Flow

One small module we write ourselves, doc/useBoard.ts. React Flow's own Yjs and dynamic grouping examples are Pro-licensed, so neither may be copied.

  • Document to UI: observeDeep rebuilds the nodes and edges. Frames sort first, because React Flow needs parents before children.
  • UI to document: dragging writes at most every 50 ms, inside one transaction.
  • Frames: child positions are relative to the parent, so they're converted on entering or leaving a frame.
  • Inside blocks: interactive content uses the nodrag, nopan and nowheel classes.

Blocks

Adding a block type means one file and one registry entry. Server-side logic (toContext, toMarkdown) lives in shared/blocks, and React lives in front_end/src/noree/blocks.

interface BlockDefinition {
  type: BlockType; label: string; icon: ReactNode
  defaultSize: { w: number; h: number }
  kind: 'work' | 'generator' | 'container'
  createContent(doc: Y.Doc, id: string): void
  Preview: ComponentType<BlockProps>     // on the board
  Focus?: ComponentType<BlockProps>      // full screen
}
interface BlockContext {                 // what a block gives to the blocks reading from it
  blockId: string; type: BlockType; title: string
  text: string; images: string[]; fingerprint: string
}
BlockOn the boardWhen openedContext it gives others
FrameTitle and regionNot applicableNot connectable in V1
TextEditable textInlineThe text
StickyColored noteInlineThe text
SlateCurrent page, read-onlyFocus mode (double-click)Transcript and page snapshots
3D modelPreview image, GenerateLive 3D in focus modePrompt and model description

Slate

  • Focus mode has pen, eraser, undo, Undo AI, previous and next page, add page, and paste of text or images.
  • Each page is its own 1600 × 1000 space, and the AI sees the current page. The agent's geometry code takes this as its world size, so it needs no changes.
  • When a page is full, the tools already return a "no room" error. V1 adds a result suggesting a new page and doesn't add pages on its own.
  • Leaving a page or closing focus uploads a PNG snapshot. Strokes are simplified before saving.

Connections and out-of-date

  • Input handle on the left, output on the right. No self links, cycles, duplicates or frames.
  • inputHash is a hash of connected blocks' fingerprints plus the prompt, and each generated version stores it.
  • If the current hash differs, the block shows Out of date and a Regenerate button.

3D rendering

Live 3D appears only in focus mode, in an iframe with sandbox="allow-scripts". The board shows the preview image, because browsers limit active WebGL contexts.

Writing agent events into the document

runAgent stays as it is, and one adapter maps its events:

EventWritten to
opcontent[slate].pages[n].objects
removeDeleted from the same map
tool, thought, stepjobs[id].steps and threads[blockId]
error, donejobs[id].status

Reading context

collectContext(blockId) finds incoming edges one step away, calls toContext on each source, and caps it at 3 images and 6,000 characters per source. A Slate's ink isn't text, so one vision call transcribes the page. The result is cached by a hash of the page and only reruns when the page changes.

The pipeline stays the same: push to main, GitHub Actions builds, S3 holds the release, SSM runs remote-deploy.sh. https://kanya.alito.tech/, /api/ and the Socket.IO endpoint all answered 200 on Nov 4. Reading the code turned up the problems below, and each fix is scheduled.

#Problem foundFixWhen

G2Sharing code between apps can break production. pm2 runs dist/main.js and rootDir is ./src. Importing from outside src would move or fail that output.shared/ is copied into each app by npm pre* hooks. deploy.yml doesn't need a change for thisM0

Security and limits

The live site has no login and pays for AI with your keys. These protect it for the judging window. They aren't a full security model, which comes with accounts later.

ThreatV1 protection
Keys leak to the browserAll model calls happen on the server. Keys stay in server-side .env files
Strangers spend your creditsHourly limits across the whole server, one job per block, one 3D job at a time, and the AI_ENABLED kill switch. Limits are global because making new projects would get around per-project ones
Guessing project linksRandom UUID ids and no list endpoint
Bad document names filling the diskHocuspocus onConnect rejects names that don't match a known project, which also blocks path tricks
Oversized messageswebsocketOptions.maxPayload and a 10 MB upload limit
Malicious uploadsPNG, JPEG and WebP only, checked by file bytes. Names are content hashes. Served with nosniff. No SVG or HTML
Generated 3D codeSandboxed iframe with no same-origin access. Code loads only from our asset path, and only the server writes it
Script injection through AI textrenderRich escapes text before inserting it and KaTeX runs in safe mode (checked). Graph expressions use the existing safe parser, with no eval
Pasted image pointing elsewhereOnly same-origin /api/assets/ URLs are rendered
Crashed job hangs foreverNo heartbeat for 60 seconds marks it failed

Known limit: anyone with a link can edit that board, and projects.json and documents sit on one disk with no backup in V1.

Definition of done

  1. Create a project and reopen it after a server restart, with nothing lost.

  6. Generate makes a real model through agent-sandbox, or fails with a clear message.
  7. Markdown export reflects the current arrangement.
