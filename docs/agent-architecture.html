Agent architecture

How the AI in Noree works: one main agent that talks to people and changes the board, and specialists that it delegates to, each with its own tools.

Written Thu Nov 5, 2026 from the code on the main-agent branch, which isn't on the live site yet. The live site still has the earlier block chat. If this file and the code disagree, the code is right, and this file should be fixed.

01

Summary

One main agent, with specialists it delegates to. There's no separate router or planner: the main agent decides what happens by choosing which tools to call. Everyone reaches it through the AI panel.

PartKindStarted byToolsCan it change the board?
Main agentAgent loop, up to 20 stepsAsk in the AI panel8 board tools and 2 specialistsYes: frames, blocks and connections. Can't delete
Slate agent (specialist)Agent loop, up to 10 stepsAsk AI in a Slate, or the main agent9 of its ownOnly annotates the Slate's current page
3D agent (specialist)Fixed pipeline, up to 3 attemptsGenerate on a 3D block, or the main agentNone: it returns code, and the pipeline tests itOnly adds a version to its block
Page transcriberOne vision call, cachedReading a Slate as contextNoneOnly stores a transcript on the page
3D brief writerOne model callGenerate, when blocks are connectedNoneNo

Tested with real models, Nov 5: in a local run with two browsers, it planned a two-frame board from one sentence in 8 s, and one Undo reversed it. It answered a question without changing anything, delegated to the Slate agent, and delegated to the 3D agent with Modal. Before building this, a test of 20 runs across both models did the right thing every time.

Rules everything follows

  1. HTTP only starts work. A request returns a job id at once.
  2. Results go into the shared document. Agents never reply to one browser, so everyone sees the same progress and closing a tab doesn't stop a run.
  3. The server owns exact values. Models never give coordinates. They name things by id, and the server works out placement.
  4. Specialists are independent. A specialist runs the same way whether a person or the main agent started it, with its own job, limits and progress on its own block. So each can be improved on its own.

02

System map

The engine

agents/engine/loop.ts is the loop every agent runs on: call the model, run its tools, feed results back, stop. It handles provider fallback, step limits and cancelling, and turns a crashing tool into an error the model can read. It knows nothing about any one agent. agents/engine/tools.ts defines a tool as a name, a description, a zod schema and a function. The schema is both what the model sees and what its input is checked against, and bad input comes back as a message it can correct.

03

Shared runtime: jobs

Every AI action runs as a job through JobsService. It connects to the project's document as a server-side peer, using a Hocuspocus direct connection, so writes reach everyone like any other edit.

Order of events:

  1. The controller validates the request and checks limits. It either refuses or returns 202 { jobId } at once.
  2. The job opens the document and writes a job record with status running.
  3. A heartbeat updates the record every 10 seconds.
  4. The work runs, adding steps and messages as it goes.
  5. The status becomes done, failed or cancelled, and the connection closes.
jobs[id] = {
  id, blockId, kind: 'main' | 'slate-run' | 'generate-3d',
  status: 'running' | 'done' | 'failed' | 'cancelled',
  steps: [{ title, status, note }],   // shown live in the activity panel
  startedBy, startedAt, heartbeatAt,
  error?,                             // a message safe to show to people
  threadId,                           // the conversation it reports to
  result?, parentJobId?,              // how a specialist reports back to the main agent
  undo?, undone?,                     // main agent runs: how to reverse its board changes
  pageId?                             // Slate runs only
}

What a job's work receives

FieldPurpose
connectionThe document, for reading and writing
signalAn abort signal, passed down to model calls and the 3D service
addStep()Adds a step to the activity panel
addMessage()Adds a message to the block's thread
fail()Marks the job failed with a message, once the work returns

Routes. Each calls one fixed function. A choice between agents only happens inside the main agent.

POST /projects/:id/blocks/:blockId/slate-run  -> runSlateJob
POST /projects/:id/agent                      -> runMainAgentJob
POST /projects/:id/blocks/:blockId/generate   -> runGenerateJob
POST /projects/:id/jobs/:jobId/cancel         -> abort signal, which also stops any specialist it started
POST /projects/:id/jobs/:jobId/undo           -> reverses a main agent run

04

Slate agent

A specialist that runs on the shared engine. It reads a page image, chooses tools, sees results, and corrects itself. The loop is in agents/slate/agent.ts, and agents/slate-run.ts connects it to the document.

How one run goes

  1. The browser renders the page to a PNG, because only the browser can draw it, and uploads it as an asset.
  2. The server reads strokes, pastes and existing AI objects from the document. Each paste becomes an outline stroke, so the agent can point at it and avoid placing anything on it.
  3. cluster.ts groups strokes into g1, g2, in reading order. The gap allowed scales with handwriting size.
  4. The model gets the system prompt, the instruction (default: "Explain what I wrote."), the image, and a text description of clusters and existing objects.
  5. Tools run. Each created object is written to the page after a 650 ms pause, so people watch them appear.
  6. When it finishes, arrows with nothing attached are removed, and the summary goes into the block's thread.

Tools

ToolWhat it doesHow it fails, so the model can correct itself

Loop behavior worth knowing

  • Maximum 10 model steps. Reaching the limit ends the run normally, with whatever was drawn.
  • One nudge. If the model replies with text and has drawn nothing, it's told once to use the tools.
  • Provider fallback mid-run. If a model call fails, the run continues on the next provider with the same conversation.
  • Empty page. The run ends without a model call.
  • It sees its earlier work. Earlier objects are in the scene, and object ids continue from them, so runs don't collide.
  • Undo AI removes every object with that run's id, and is a normal action any person can take.

05

Main agent

The one agent people talk to, in agents/main-agent.ts. It replaces the earlier block chat. With nothing selected it works from the board, and with a block selected it starts from that block and what's connected to it. A simple question takes one model step, so it stays as fast as chat was.

One turn

  1. Read the last 10 messages of the conversation. The board has its own, and each block has its own, shared by everyone.
  2. Add the person's request to the conversation. The server does this, so a refused request leaves no orphan message.
  3. Send the model a summary of the whole board with ids, so it starts grounded without spending a step to look. With a block selected, add its content, its connected blocks and up to 3 images.
  4. Run the loop until the model replies with no tool calls, for up to 20 steps.
  5. Add the reply to the conversation.

Specialists

agents/subagents.ts is the list of specialists. Adding one means adding one tool to that list, and the main agent picks it up. Each starts as its own job on its own block, using the same functions as the block's own button, so it gets the same limits, progress and history. It returns a short result, not its whole transcript, which keeps the main agent's context small. Stopping the main agent stops any specialist it started.

When a specialist works on the block whose conversation the main agent is in, it stays quiet and the main agent reports, so people hear one voice. Otherwise it also leaves its own message on its block.

Placement

Models never give coordinates. shared/layout.ts places everything: new frames to the right of everything, blocks inside a frame in rows that fit its width, and loose blocks above the frames. Frames only grow downward, so a batch of additions in any order can't overlap. New blocks are brought into view for the person who asked, as they appear.

Undo

Each change records how to reverse itself on the job, so one Undo reverses a whole run, even after a reload or a restart. The undo also goes in the conversation, or the agent's history would still say its work was on the board. Slate annotations and 3D versions keep their own undo, because they belong to their blocks.

Limits

  • 20 steps per turn, and 30 new blocks per turn. Testing showed one model can over-build.
  • One main agent run per board. A request made while it's busy elsewhere is told so, and the panel says why.
  • It can't delete. That's held for ask_question, so it can confirm first.

06

Page transcriber

Handwriting isn't text, so when the main agent or 3D reads a Slate, one vision call turns a page into text.

  • Cached on the page. The key is the snapshot's file name, which is a hash of its content. Same picture, same transcript, no second call.
  • Limit: 3 pages per Slate, current page first.
  • If it fails: the source says it couldn't be read, plus any pasted text, and the main answer still goes ahead. The failure isn't cached, so it retries next time.
  • Snapshots are saved 3 seconds after a change while a Slate is open, and again when leaving a page or closing.

07

3D generation

A fixed pipeline, in two parts. The Nest job in agents/generate3d.ts prepares and tracks the run. The Python service in services/agent-sandbox writes, tests and reviews the code, and is called over HTTP on localhost.

Steps

  1. Fix the input hash. It's recorded at the start, so edits made during the run correctly show the result as out of date.
  2. Collect context from connected blocks, transcribing Slates if needed. With no prompt and no connections, it stops and asks for a prompt.
  3. Write the brief. With connections, one model call turns the prompt, text and images into at most 60 words. With no connections, the prompt is the brief, with no model call.
  4. Call the service. POST /generate blocks until it's finished, and can take minutes, so Nest uses a client with a 30-minute timeout.
  5. Report progress. Every 2 seconds, Nest reads GET /runs and copies new steps into the job. It finds the right run by ignoring runs that existed before it started and matching the prompt, because the service only returns the run id at the end.
  6. Save the result. Nest copies the code and preview into the project's assets, adds a version, and makes it current. Earlier versions stay.

Inside the service

StageWhat happensOn failure
Coding agentDespite the name, a single model call per attempt, not an agent loop. It returns one ES module that exports create(container, context) and may only import from three. It has no tools. A retry sends the brief plus the failure notes, but not the previous code, so each attempt rewrites from scratchA raised error fails the whole run
Modal testA Modal sandbox runs the code in headless Chromium with software WebGL for 3.5 seconds, collects console errors, takes a screenshot and checks it isn't blank. The sandbox is always terminatedErrors go back as feedback, and review is skipped for that attempt
Vision reviewA vision model reads the brief and the screenshot, and replies PASS or FAIL with notesNotes go back as feedback. If the vision call itself errors or returns nothing, the attempt is accepted on the sandbox test alone
After 3 attemptsThe last code is saved as a draftThe block shows it with a Draft badge, and the review note goes in the thread

Displaying the result

Generated code is served as plain text, and only runs inside an iframe with sandbox="allow-scripts", with no same-origin access. The board shows the preview image, and live 3D appears only in focus mode, because browsers limit active WebGL contexts.

Out-of-date detection

The input hash covers the prompt plus a fingerprint of each connected block. Moving or renaming a source doesn't change it. Both browser and server compute it from shared/fingerprint.ts, so the badge is live and needs no request. Nothing regenerates by itself.

09

Context

collectContext in agents/context.ts gives the main agent and 3D what they read. A line from A to B means B reads from A, one step only.

BlockText it givesImages it gives
Text, StickyIts contentNone
SlateTranscript of up to 3 pages, current firstSnapshots of those pages
3D modelIts brief, or its prompt if not generated yetIts preview
FrameCan't be connected

Limits: 6,000 characters per block, and 3 images in total, with sources served before the block's own.

Prompt injection: the main agent and brief prompts say block content is information, not instructions. That's a mitigation, not a guarantee. The main agent has tools, so text on a board could try to steer it, but it can't delete, and one Undo reverses its changes. Generated code runs sandboxed. The Slate agent's prompt has no such line, so see section 11.

What doesn't exist yet

The main agent closed the biggest gap. These are the ones left, roughly in the order I'd take them.

GapTodayWhy it matters next
It can't ask you anythingNo ask_question, so it can't pause, offer choices or confirm. That's also why it can't deleteThe next main agent feature. Needs pausing and resuming a run
Long specialists hold up the turnThe main agent waits for a specialist to finish, and runs them one at a timeStarting one and carrying on would make it feel much faster
Replies don't streamA reply appears when it's completeNoticeable on longer answers
The Slate agent ignores connections and its conversationIt only sees its own page, and each run starts freshA Slate can't yet build on other blocks, and follow-ups lose context
The main agent can't write on a SlateIt can create one but not put content on it. Page images only come from a browser"Work this out on a Slate" isn't possible yet
Agents write directly in placesBoard structure uses the action layer. Text, prompts, Slate objects and messages are direct writesWorth moving to actions for validation and authorship
No shared memoryConversations are per block and per board, and aren't read across each otherNothing carries what was learned between conversations
No token budgetLimits count runs and steps, not tokens or costLonger autonomous runs need budgets
Everything needs a person to start itNo background or scheduled runsAutonomous agents would need approval rules
Slate prompt-injection hardeningIts prompt doesn't say that page content is only information, and pasted text reaches itWorth adding. Damage is limited, since its tools can only annotate that page
The 3D coding agent can't iterateOne call per attempt, no tools, and retries don't see the previous codeA good model with one small flaw gets thrown away and rewritten, which can fix one thing and break another
Reviewer can pass on failureIf the review call errors, the attempt is accepted on the sandbox test aloneApproved may mean "rendered" rather than "reviewed" when the vision call is down
Cancel isn't authorizedAnyone with a job id can stop that job. Ids are random and visible to people on that boardFine for links with no accounts. Revisit with accounts

How to extend it: a new specialist is one tool in agents/subagents.ts, with its own function and its own tools on the shared engine. It can be improved and tested alone, through its own button, and the main agent can use it right away.
